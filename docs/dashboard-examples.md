# 대시보드 예제

기존 관리자 레이아웃 안에서 서로 다른 조회·분석 패턴을 제공한다.

| 경로          | 화면          | 주요 기능                                                                |
| ------------- | ------------- | ------------------------------------------------------------------------ |
| `/`           | 종합 대시보드 | 매출·사용자 KPI, 월별 매출, 방문·전환 추이, 카테고리 매출, 주문 검색·CSV |
| `/operations` | 프로젝트 운영 | 일정 타임라인, 담당자별 남은 작업, 마감 점검, 프로젝트 진행률            |
| `/reports`    | 분석 리포트   | 완료 작업 수/공수 지표 전환, 직전 기간 비교, 프로젝트별 집계, CSV        |

## 종합 대시보드: 매출과 주문

`design-system-sample/sample/design-showcase/layout/layout-dashboard.html`의 본문 콘텐츠를 React로 옮긴 예제다. 사이드바와 GNB는 공통 레이아웃을 사용한다.

- `GET /api/dashboard/commerce`를 TanStack Query로 조회하고 Zod로 검증한다. 기준일은 `2025-06-30`이며, 실제 운영 데이터가 아닌 고정 샘플이다.
- 총 매출 420만 원·신규 사용자 1,284명·전환율 3.6%·활성 세션 847개, 월별 매출 7개·일별 방문/전환 14개·카테고리 4개·최근 활동 5개·주문 23건을 제공한다. 세션 수와 활동 시각은 기준일의 스냅샷이다.
- 원본의 카테고리 금액 단위를 원으로 통일해 합계 420만 원과 일치시켰다. 전월 400만 원 대비 증가는 5.0%로 계산한다. 최근 주문 표는 검색 표와 같은 주문 객체를 사용하므로 금액·상품명이 일치한다.
- 월별·카테고리 매출은 월 전체 요약이고 주문 23건은 별도 목록 예제다. 주문 필터는 KPI·차트에 적용되지 않는다. 주문 담당 CS는 필터 예제를 위한 가상 배정이다.
- 주문번호·고객·상품·브랜드 검색, 상태, 기간, 금액, 카테고리, 브랜드 복수 선택, 담당 CS, 정렬, 페이지 이동을 지원한다. 날짜/금액 역전은 입력 오류로 표시한다.
- 주문 필터는 적용 버튼을 눌러 반영한다. 작성 중 조건·적용 조건·페이지·선택은 화면의 지역 상태로, 종합 화면을 떠나거나 새로고침하면 초기화한다. 프로젝트 대시보드의 URL 조건과는 분리한다.
- 체크박스는 현재 페이지의 주문을 선택한다. 필터·정렬·페이지 변경 시 선택을 지운다. 선택이 있으면 선택 주문만, 없으면 검색 결과 전체를 CSV로 내보낸다. 빈 결과에서는 내보내기를 비활성화한다.
- 상단 내보내기는 전체 KPI/매출 요약을 내려받는다. 새 보고서는 이름을 입력하고 같은 요약을 CSV로 생성한다. 보고서를 서버에 저장하지 않는다.
- React가 SVG 막대·선·도넛 차트를 소유한다. 기간/수치 축과 카테고리 비중을 표현하고, 포인터·날짜 선택·범례 포커스로 세부 수치를 확인한다. 월별 매출은 막대 호버·Tab 포커스·터치로 월과 정확한 금액을 조회하고 Escape로 툴팁을 닫는다. 월별·방문 차트에는 원본 데이터 표도 제공한다. 차트 3개와 최대 8개 검색 행을 렌더하며 추가 라이브러리는 없다.

## 프로젝트 운영·분석 리포트의 데이터와 집계 기준

- 두 화면은 `GET /api/dashboard`를 TanStack Query로 조회하고 Zod로 응답을 검증한다.
- MSW는 기존 `/api/projects`와 같은 프로젝트 저장소를 사용한다. 프로젝트 생성·상태 변경은 목록과 대시보드 query를 함께 무효화한다.
- 작업 fixture 96개는 고정된 샘플 기준일 `2026-07-15`에 맞춰 생성한다. 실시간 운영 데이터가 아니며 기준일을 화면에 표시한다.
- 최근 N일은 기준일을 포함하는 N개의 UTC 날짜다. 비교 기간은 그 직전의 겹치지 않는 N일이다.
- 완료 작업 수와 공수는 `completedAt`이 선택 기간 안에 있는 작업을 집계한다. 공수는 해당 완료 작업에 기록된 시간의 합이며, 근무시간이나 실제 인력 가동률을 의미하지 않는다.
- 프로젝트 수·상태·전체 작업 진행률·미완료 작업은 기간별 이력이 아닌 기준일 현재 값이다. 기간 선택은 이 값들을 바꾸지 않는다. 담당자·상태 조건은 모든 집계에 동일하게 적용한다.
- 프로젝트 담당자별 업무량은 해당 프로젝트들의 미완료 작업 수다. 개별 작업자 배정이나 인력 가동률 예제는 포함하지 않는다.
- 마감 지연은 기준일 이전에 마감된 미완료 작업이다. 기준일 당일 마감은 지연이 아니며, 마감 예정에 포함한다.
- 신규 프로젝트처럼 작업이 없으면 진행률은 `—`로 표시한다. 실제 0%와 구분한다.
- 이전 실적이 0이면 증가율을 계산하지 않고 이전 실적이 없다고 표시한다.

## 프로젝트 화면 필터와 탐색

`days=7|30|90`, `owner`, `status=all|active|paused|completed`,
`metric=completed|hours`를 URL search에 저장한다. 프로젝트 운영·분석 리포트 사이의 탭은
조건을 유지하고, 종합 대시보드는 독립 콘텐츠로 이동한다. 사이드바는 각 화면의 기본 조회로 이동한다. 새로고침과 뒤로
가기에서도 URL 조건이 복원된다. 알 수 없는 담당자는 빈 결과로 표시하고
초기화를 제공하며, 잘못된 기간·상태·지표 값은 기본값으로 정규화한다.

## 로그인 후 공통 레이아웃

- 사이드바는 대시보드·워크스페이스·환경 그룹으로 구분한다. 현재 화면의 그룹은 자동으로 펼쳐지고 활성 메뉴를 표시한다.
- GNB의 검색창이나 `Cmd/Ctrl + K`로 메뉴 검색을 연다. 메뉴·그룹 이름으로 검색하며 방향키·Enter 또는 클릭으로 이동한다. 데이터 본문 검색은 포함하지 않는다.
- 검색과 사이드바 이동은 기본 조회 조건을 사용한다. GNB 아래 현재 위치에는 그룹·화면·프로젝트 상세의 상위 목록 링크를 표시한다.
- 로그인한 계정의 이메일·이니셜, 테마 전환과 로그아웃을 GNB에 표시한다.
- 데스크톱 사이드바는 항상 표시하고 햄버거 버튼은 모바일 GNB 왼쪽에만 표시한다. 모바일 메뉴는 처음에 닫혀 있는 모달 서랍이다. Escape·배경 클릭·메뉴 이동으로 닫히며 포커스는 열기 버튼으로 돌아온다.
- 메뉴 레지스트리 `src/layouts/navigation.ts`를 사이드바·검색·현재 위치에서 공유한다.

## 표시와 접근성

React가 SVG를 직접 렌더링하며 별도 차트 의존성은 없다. 프로젝트 리포트의 선택 기간은 실선,
이전 기간은 점선으로 구분하고 0을 기준으로 같은 Y축을 사용한다. 일별 원본
수치는 펼칠 수 있는 표로 제공한다. 막대 수치와 일정·진행률은 텍스트로도
표시한다. 모바일에서는 패널이 한 열로 배치되고 넓은 표만 내부 스크롤한다.

로딩, 오류 후 재시도, 빈 결과, 완료 실적 0을 처리한다. 새로고침 실패 시
기존 데이터와 오류 메시지를 함께 표시한다. CSV는 현재 필터의 프로젝트별
집계이며, BOM·인용부호 이스케이프·수식 시작 문자 방어를 포함한다.

## 검증

집계 경계·이전 기간·필터·빈 데이터·응답 스키마는 Vitest로 검증한다.
컴포넌트 테스트는 실제 메모리 라우터와 MSW를 사용한다. Playwright는 화면
이동, URL 복원, 다운로드, 390px/1280px 레이아웃과 다크 모드를 확인한다.
공통 레이아웃은 그룹 탐색·검색 키보드 조작·빈 결과·모바일 포커스 제한과 복원을 검증한다.
`pnpm verify`로 전체 품질 게이트를 실행한다.

## 공통 하단 레이아웃

- 모바일·태블릿(1024px 미만)은 홈·운영·분석·프로젝트·설정 고정 메뉴를 제공한다.
  프로젝트 상세에서도 프로젝트 탭이 활성화된다. 서랍을 열면 하단 메뉴는 모달 배경으로 비활성화된다.
- 데스크톱은 앱 정보, 도움말, 저장소 링크와 설정을 푸터에 표시한다.
- 본문 마지막 행과 토스트는 하단 메뉴에 가리지 않도록 안전 영역을 포함한 여백을 확보한다.
