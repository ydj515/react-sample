# 랜딩 페이지 예제

## 진입 경로

관리자 사이드바의 **샘플 → Landing Pages** 또는 `/landing`에서
로그인 없이 여섯 가지 랜딩을 탐색한다.

| 경로               | 목적                 | 주요 구성                                             |
| ------------------ | -------------------- | ----------------------------------------------------- |
| `/landing`         | 샘플 선택            | 랜딩 카드, Docs·쇼핑·관리자 연결                      |
| `/landing/saas`    | SaaS 제품 소개       | 보드 미리보기, 기능, 워크플로우, 요금제, FAQ          |
| `/landing/course`  | 온라인 강의 소개     | 공개 수업, 학습 목표, 커리큘럼, 강사, 수강권, FAQ     |
| `/landing/agency`  | 디자인 스튜디오 소개 | 작업 필터, 사례 상세, 프로세스, 서비스, 프로젝트 문의 |
| `/landing/event`   | 컨퍼런스             | 프로그램 필터, 관심 세션, 연사, 참가권                |
| `/landing/stay`    | 부티크 숙소          | 사진 히어로, 객실 비교, 날짜·정원 검증, 견적          |
| `/landing/product` | 오디오 제품          | 제품 사진, 특징 전환, 사양, 구성·수량 선택            |

## 구성과 재사용

`src/routes/landing.*.tsx`는 페이지 연결만 담당한다.
페이지는 `src/features/landing/pages/{saas,course,agency,event,stay,product}`에서 자신의
헤더, 본문 순서, 푸터를 조합한다. 모든 화면을 하나의 variant 기반
레이아웃으로 묶지 않는다.

- `LandingContainer`: 콘텐츠 너비와 좌우 여백
- `LandingSection`: 섹션 간격과 고정 헤더를 고려한 앵커 여백
- `LandingPage`: 문서 제목과 본문 건너뛰기 링크
- `LandingMenu`: Radix Dialog 기반 모바일 메뉴, 닫기·Escape·포커스 복귀
- `LandingFaq`: 키보드로 조작할 수 있는 네이티브 details/summary
- `InquiryForm`, `InquiryDialog`: 공통 데모 입력 검증과 완료 안내

이 컴포넌트들은 랜딩 feature 내부에서 재사용한다. 전역 색상·타이포·버튼·
입력·테마 컨트롤은 기존 디자인 시스템을 사용하며, 별도 라이브러리나
전역 CSS 덮어쓰기를 추가하지 않는다.

## 상호작용과 상태

- SaaS: 월간·연간 전환은 로컬 상태다. 연간은 월간 금액의 20% 할인,
  월 환산 금액 × 12를 연간 합계로 표시한다. 신청 창에는 선택한
  플랜과 주기의 합계를 전달한다. 새로고침하면 월간으로 돌아간다.
- 강의: 4개 챕터·12개 수업·총 5시간의 가상 구성이다. 첫 수업은
  영상 대신 텍스트와 코드로 제공한다. 수강권 신청에 플랜과 금액을 표시한다.
- 에이전시: 4개 가상 프로젝트를 분야별로 필터하고 상세 다이얼로그에서
  문제와 접근 방식을 읽는다. 작업 분야 필터는 URL의 `category`로 복원한다.
- 컨퍼런스: 행사 날짜와 분야를 조합해 세션을 필터하고 관심 세션을
  담거나 해제한다. 날짜/분야는 URL의 `day/track`으로 복원한다. 관심 목록은 날짜를 바꿔도 유지하며 새로고침하면 초기화한다.
- 숙소: 객실 상세를 전환해 비교한다. 별도의 여정 폼에서 날짜, 객실,
  인원을 선택하며 실제 예약 가능 여부는 조회하지 않는다. 오늘 이전 날짜,
  체크아웃 역전·동일 날짜, 14박 초과, 객실 정원 초과를 Zod로 검증한다.
  UTC 자정 차이로 박수를 계산해 일광 절약 시간의 영향을 피한다.
  견적 표시 후 입력을 바꾸면 이전 금액을 지워 잘못된 일정과 혼동하지 않는다.
- 오디오 제품: 특징 버튼으로 설명을 전환하고 Solo/Studio set 및 1~3개
  수량을 선택한다. 화면 합계와 신청 창의 구성이 같은 상태를 사용한다.
- 섹션 이동은 URL hash를 사용하며 직접 접근과 새로고침을 지원한다.
- 문의·신청은 React Hook Form과 Zod로 이름·이메일·문의 내용을 검증한다.
  입력값을 API, 이메일 또는 로컬 스토리지로 전송·저장하지 않는다.
  완료 안내는 현재 컴포넌트에만 유지하며 다시 작성 시 입력을 초기화한다.

모든 브랜드, 강사, 요금과 포트폴리오는 가상 콘텐츠다. 실제 계정 생성,
구독, 결제, 수강 등록 또는 프로젝트 문의 접수는 구현하지 않는다.

## 확인과 검증

Storybook의 `Pages/Landing`에 컬렉션과 6종 랜딩의 기본·모바일·다크
스토리를 제공한다. `Features/Landing`에서는 요금 전환, 필터, 미리보기,
FAQ와 폼의 오류·완료 상태를 확인한다.

단위·컴포넌트 테스트는 가격 계산, 입력 검증, 화면 이동, 선택 결과와
다이얼로그 동작을 검증한다. `e2e/landing.e2e.ts`는 390px·1440px에서
모바일 메뉴, 앵커/새로고침, 테마, 신청과 탐색 흐름을 검증한다.
최종 검증 명령은 `mise exec -- pnpm verify`다.

## 참고 사이트와 디자인 적용

2026-09-09에 공개 페이지를 확인했다. 레이아웃 원칙을 참고하며, 실제
브랜드의 문구·이미지·고객 실적을 샘플 콘텐츠로 복제하지 않는다.

| 참고 사이트                                                        | 관찰한 요소                                              | 샘플에 적용한 방식                                              |
| ------------------------------------------------------------------ | -------------------------------------------------------- | --------------------------------------------------------------- |
| [Stripe Sessions](https://stripe.com/sessions/2026)                | 큰 행사 제목, 구획을 나누는 배경 그래픽, 세션별 탐색     | OFFSCRIPT의 큰 타이포, 격자·링 그래픽, 날짜/트랙 필터           |
| [Aman](https://www.aman.com/)                                      | 따뜻한 중성 배경, 세리프 제목, 넓은 사진과 비대칭 콘텐츠 | ONYU의 올리브·크림 팔레트, 사진 히어로, 객실/서사 교차 구성     |
| [Nothing Headphone (1)](https://nothing.tech/products/headphone-1) | 몰입형 제품 이미지, 디자인/컨트롤/사양 전개              | FORMA의 제품 중심 히어로, 모노스페이스 라벨, 특징 전환과 사양표 |

`pages/experience.css`는 `.landing-event`, `.landing-stay`,
`.landing-product` 내부에서만 기존 의미 기반 색상 토큰을 재정의한다.
라이트/다크 팔레트를 각각 제공하며 기존 3종과 관리자 UI의 전역 토큰을
변경하지 않는다. 포털로 표시하는 공통 메뉴·신청 창은 앱의 기본 테마를
그대로 사용한다.

숙소 외관·침실과 헤드폰 사진은 AI로 생성한 원본 콘셉트이며
`public/landing-images`에서 로컬로 제공한다. 이미지 출처와 용도는
해당 디렉터리의 README를 참고한다. 사진 영역에 크기를 명시하고,
첫 화면 이미지는 우선 로드, 하단 이미지는 지연 로드한다.

앱은 PNG 원본 대신 480·960·1536px WebP와 레이아웃별 `sizes`를 사용한다.
숙소 모바일 히어로는 `picture`로 360·600px 세로 구도를 선택한다.
원본과 생성 출처는 보존하며 인코딩 설정과 파일 크기는 이미지 README에 기록한다.
컨퍼런스 참가권 버튼은 테마와 관계없이 어두운 배경·포커스 테두리를
사용한다. Storybook의 `DarkTicketFocus`에서 키보드 포커스를 확인한다.

추가 검증: `e2e/landing-experiences.e2e.ts`에서 390px·1440px의
이미지 로드, 메뉴, 섹션 링크와 테마를 확인하고 320px 가로 넘침도 검사한다.
세션의 빈 결과 복구, 날짜/정원 오류, 구성과 신청 금액 일치도 검증한다.
