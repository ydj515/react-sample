# 칸반 보드 예제

`/kanban` 라우트에서 4개 컬럼(백로그/진행 중/리뷰/완료)의 작업 흐름을 드래그&드롭으로
관리하는 예제다. 카드를 옮기면 TanStack Query의 옵티미스틱 업데이트로 즉시
위치가 바뀌고, 서버가 거절하면 변경 전 상태로 롤백한다. 컬럼·우선순위·담당자·키워드
필터는 URL `search`로 저장되어 공유·복원이 가능하다.

| 경로      | 화면      | 주요 기능                                                                    |
| --------- | --------- | ---------------------------------------------------------------------------- |
| `/kanban` | 칸반 보드 | @dnd-kit 드래그&드롭, 옵티미스틱 이동/롤백, 컬럼/우선순위/담당자/키워드 필터 |

## 드래그&드롭

`@dnd-kit/core` + `@dnd-kit/sortable`을 사용한다. 카드 본문을 포인터로 끌거나
이동 버튼에 초점을 맞추고 Space/Enter와 방향키로 조작한다.

- 포인터가 카드의 위쪽 절반에 있으면 앞에, 아래쪽 절반에 있으면 뒤에 삽입한다.
- 카드 사이 간격과 컬럼의 빈 영역도 가까운 삽입 위치로 해석한다.
- 화면에는 이동 카드 높이의 옅은 빈자리 하나만 표시한다. 카드들이 자리를
  비켜주며, 별도 안내 행이나 "여기에 카드 놓기" 배지를 추가하지 않는다.
- 미리보기 목록이 이미 공간을 확보하므로 sortable의 추가 밀어내기는 사용하지 않는다.
- 다른 카드의 위치 변화는 160ms로 표시한다. 모션 감소 설정에서는 생략한다.
- 미리보기에서 확정한 컬럼과 순서로 저장한다. 같은 컬럼에서 한 칸 아래로
  이동하는 경우도 정상 처리한다. Esc 또는 보드 밖 드롭은 저장하지 않는다.
- `resolveMoveIndex`는 필터로 보이는 위치를 전체 카드 목록의 저장 인덱스로
  변환한다. 다음 보이는 카드 앞에 삽입하고, 마지막이면 직전 보이는 카드 뒤에
  삽입한다. 보이는 카드가 없으면 숨겨진 카드를 포함한 컬럼 끝에 추가한다.
- `DragOverlay`는 원래 크기의 카드를 작은 그림자와 함께 표시한다.

## 옵티미스틱 이동과 롤백

`useMoveKanbanCardMutation`은 다음과 같이 동작한다.

1. `onMutate`에서 보드 캐시를 취소하고 `applyMoveLocally`로 즉시 새 위치를
   반영한다. 반환된 `previousBoard`를 컨텍스트에 저장한다.
2. 서버가 성공하면 `onSettled`에서 보드 쿼리를 무효화해 서버 데이터와 동기화한다.
3. 서버가 `INVALID_MOVE`(409) 등으로 실패하면 `onError`가 컨텍스트의
   `previousBoard`를 그대로 복원해 카드가 출발 위치로 돌아간다.
4. UI는 실패 토스트를 띄우고 드래그 상태를 초기화한다.

서버가 항상 거절하는 fixture 카드로 API 오류와 실제 드래그 롤백을 검증한다.
`applyMoveLocally`는 원본 카드를 복사하므로 복원용 캐시의 순서를 변경하지 않는다.

## 필터와 URL 상태

`kanbanSearchSchema`는 다음 4개 필드를 가진다.

- `q`: 제목·설명·담당자·태그를 모두 검색한다.
- `column`: 특정 컬럼만 보여준다.
- `priority`: 카드 우선순위로 좁힌다.
- `assignee`: 담당자 ID로 좁힌다.

URL `search`가 바뀌면 `loaderDeps` 없이 페이지가 다시 그려지고 같은 키로
`useKanbanBoardQuery`가 재평가된다. 검색·필터 변경은 즉시 결과에 반영되며
새로고침·뒤로 가기에도 그대로 복원된다.

## 접근성과 모션

- 이동 버튼에는 카드 제목을 포함한 이름과 키보드 조작 설명을 제공한다.
- Space/Enter로 잡기와 놓기, 방향키로 이동, Esc로 취소한다.
- 현재 컬럼과 순서를 단일 `role="status"` 영역으로 안내한다.
- 이동 종료 후 버튼에 초점을 복원한다. 저장 중에는 추가 드래그를 막는다.
- 컬럼 헤더는 `<h3>`로, 카드 수는 `aria-label`로 제공한다.
- 저장 중 `aria-busy`를 표시하고, 모션 감소 설정에서는 위치 애니메이션을 생략한다.

## Mock API와 검증

- `src/mocks/data/kanban.ts`의 fixture는 16장의 카드와 4개 컬럼으로 구성된다.
  그중 "테스트 실패: 강제 시뮬레이션" 카드는 어떤 위치로 옮겨도 409로
  거절되어 옵티미스틱 롤백을 확인할 수 있다.
- 핸들러는 보드 조회·카드 이동을 담당하고 잘못된 본문은 400을 반환한다.
- API 통합 테스트는 다음을 검증한다.
  - 보드 컬럼/카드 응답 형태
  - 같은 컬럼 내 재정렬과 컬럼 간 이동
  - "테스트 실패" 카드의 409 응답
  - 없는 카드 ID의 404 응답
  - 응답 스키마 위반의 `INVALID_RESPONSE` 처리
- 쿼리 단위 테스트는 `applyMoveLocally`가 컬럼 내부/사이를 일관되게
  재정렬하는지 검증한다.
- 통합 페이지는 메모리 라우터와 MSW로 다음을 검증한다.
  - 4개 컬럼과 모든 카드 렌더
  - 컬럼/우선순위 필터가 결과 카드를 좁힘
  - 초기화 버튼이 필터를 모두 해제
  - "테스트 실패" 카드 이동 시 409로 거절되고 카드가 원래 위치에 머무름
- jsdom은 `IntersectionObserver`를 제공하지 않으므로 `src/test/setup.ts`에서
  안전한 noop 스텁을 등록한다.
