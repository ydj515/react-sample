# CRM 예제

`/crm`은 회사, 연락처, 딜, 활동 내역의 관계를 보여주는 로그인 필요 예제다.
`/crm/contacts/$contactId`에서 담당자별 딜과 메모를 함께 확인한다.

## 관계 모델과 상태

회사는 여러 연락처를 갖고 연락처는 하나의 회사에 속한다.
딜은 연락처 ID를 참조하고 활동 내역도 연락처 ID를 참조한다.
API 입력과 응답에서 연결 대상이 실제 존재하는지 검사한다.
회사 데이터는 고정 fixture이며 연락처와 딜을 화면에서 추가할 수 있다.

- 딜 단계: 신규(`lead`), 상담(`qualified`), 제안(`proposal`), 성사(`won`), 종료(`lost`).
- 금액은 0 이상 1조 원 이하의 정수다.
- 딜 생성과 단계 변경은 연결된 연락처의 활동 내역에 기록된다.
- 같은 단계로 다시 저장해도 중복 활동을 만들지 않는다.
- 메모는 1~2,000자이며 저장 후 활동 내역에 표시된다.

회사와 연락처 검색은 `company`, `q` URL search로 유지된다.
연락처를 필터링하면 딜 파이프라인도 같은 연락처 집합으로 좁혀진다.
각 단계에 현재 필터 결과의 금액 합계를 표시한다.

## 상호작용과 실패 처리

딜은 포인터 드래그로 단계를 바꾸거나 카드의 선택 상자로 이동할 수 있다.
키보드 사용자는 선택 상자로 같은 작업을 수행한다. 드래그 영역 밖에
놓으면 저장하지 않는다. 단계 저장 중 추가 이동을 막고, 성공 후 데이터를
재조회한다. 서버 승인 전 캐시를 변경하지 않으므로 실패 시 기존 단계가 유지된다.
연락처·딜·메모 저장 오류는 해당 폼에 표시하며 입력을 보존한다.

## API

| 메서드·경로                        | 작업                                |
| ---------------------------------- | ----------------------------------- |
| `GET /api/crm`                     | 회사·연락처·딜·활동의 일관된 스냅샷 |
| `POST /api/crm/contacts`           | 연락처 생성                         |
| `POST /api/crm/deals`              | 딜 생성과 활동 기록                 |
| `POST /api/crm/deals/:id/stage`    | 단계 변경과 활동 기록               |
| `POST /api/crm/contacts/:id/notes` | 연락처에 메모 추가                  |

생성 성공은 201, 단계 변경은 200이다. 입력이나 관계 위반은 400,
존재하지 않는 변경 대상은 404다. 표준 오류 응답에 trace ID를 포함한다.
상태는 MSW 메모리에만 저장하고 새로고침/테스트 초기화 시 fixture로 돌아간다.
실제 영업 권한, 통화/메일 연동, 매출 확정 처리는 포함하지 않는다.

## 검증

`pnpm exec vitest run src/features/crm`은 관계 무결성, 연락처·딜 생성,
단계 변경, 메모와 필터 흐름을 확인한다.
`pnpm exec playwright test e2e/crm.e2e.ts`는 브라우저에서 관계 생성과
활동 내역을 확인한다. `Features/CRM/DealPipeline`에 단계별 화면 예제가 있다.
