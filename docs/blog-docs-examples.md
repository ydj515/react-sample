# Blog / Docs 예제

## 진입과 화면 구성

- `/docs`는 `/docs/getting-started`로 이동한다.
- `/docs/$slug`는 로그인 없이 읽을 수 있는 공개 문서 경로다.
- 관리자 사이드바의 **샘플 → Blog / Docs** 또는 전역 검색에서 진입한다.
- 시작하기, 컴포넌트 설계, 서버 상태, 폼 검증, 테스트의 5개 문서를 제공한다.
- 데스크톱에서는 문서 탐색·본문·목차를 배치한다. 1280px 미만에서는
  목차를 본문 위 접이식 메뉴로, 1024px 미만에서는 문서 탐색을
  모바일 다이얼로그로 전환한다.

## 상호작용

- 검색은 제목·설명·섹션 제목·본문·목록·코드에서 대소문자 구분 없이
  문자열을 찾는다. 본문 일치는 첫 번째 일치 섹션으로 연결한다.
- 결과는 문서별로 하나씩 표시한다. 검색어가 없으면 결과 창을 닫고,
  빈 결과에는 안내를 표시한다. Escape 또는 닫기로 검색을 초기화한다.
- 목차는 앵커 링크를 사용하며, 스크롤 중 보이는 섹션을 강조한다.
  URL의 hash로 섹션을 직접 공유할 수 있다.
- 코드 복사는 Clipboard API를 사용한다. 브라우저가 복사를 거부하면
  코드를 유지하고 직접 선택하여 복사하도록 안내한다.
- 이전·다음 문서는 카탈로그 순서를 따른다. 알 수 없는 slug는 문서
  레이아웃 안에서 복구 링크와 함께 안내한다.
- 테마는 기존 공통 테마 설정을 공유한다. 문서 화면은 관리자 사이드바와
  독립된 레이아웃을 사용한다.

헤더 아래 읽기 진행률은 현재 페이지의 스크롤 가능한 높이를 기준으로
0–100%를 표시한다. 스크롤, 창 크기와 콘텐츠 높이 변경 시 다시 계산하고,
문서 이동 시 새 페이지에 맞춰 갱신한다. 스크롤이 필요 없는 짧은 페이지는
100%로 표시한다.

## 콘텐츠와 코드 배치

`src/features/docs/model/documents.ts`가 정적 문서 카탈로그를 소유한다.
본문은 paragraph, list, code, note 블록으로 구성하고 React로 렌더링한다.
임의 HTML이나 외부 Markdown을 실행하지 않으며 별도 라이브러리를 추가하지 않는다.
정적 콘텐츠이므로 문서용 MSW API나 TanStack Query 캐시는 만들지 않는다.

문서를 추가할 때 고유한 slug와 섹션 id를 지정한다. 제목과 본문은 검색에
자동 포함되며, 카탈로그 순서가 왼쪽 탐색과 이전·다음 이동의 기준이 된다.
문서 편집기, 댓글, CMS 연동, 게시물 작성 기능은 현재 범위에 포함하지 않는다.

## 검증과 Storybook

- 모델 테스트: 고유 URL과 제목·본문 검색.
- 컴포넌트 테스트: 복사 성공·실패, 검색 결과·빈 결과, 문서 이동과 복구.
- E2E: 공개 경로, 섹션 직접 진입·새로고침, 실제 클립보드,
  모바일 메뉴·목차·테마, 관리자에서 진입.
- Storybook: `Pages/Docs`, `Features/Docs/Search`, `Features/Docs/CodeBlock`.

```bash
pnpm test src/features/docs
pnpm test:e2e e2e/docs.e2e.ts
pnpm verify
```
