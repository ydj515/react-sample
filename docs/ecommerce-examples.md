# E-commerce 예제

## 화면과 진입 경로

- `/shop`: 카테고리·브랜드·가격대·재고·찜 필터, 검색, 정렬, 공통 페이지네이션.
- `/shop/$productId`: 상품 이미지 확대, 정보·리뷰 탭, 색상·사이즈·수량 선택,
  장바구니 담기와 관련 상품.
- `/shop/cart`: 옵션별 수량 변경·삭제, 재고 경고, 가격·배송비 요약.
- `/shop/checkout`: 배송 정보 검증, 모의 주문 완료와 영수증.
- 관리자 메뉴의 **샘플 → E-commerce** 또는 전역 검색에서 이동한다.
  쇼핑 경로는 로그인 없이 사용할 수 있다.

## 기존 관리자 예제와의 관계

기존 `products` API·query·응답 모델과 이미지를 재사용한다. 목록과 상세는
`active` 상품만 표시하며 품절 상품은 담을 수 없다. 관리자에서 상품을
수정하면 같은 Query key를 사용하는 쇼핑 화면도 갱신한다.

새 API는 `POST /api/shop/orders` 하나다. MSW handler는 요청 스키마,
상품 판매 상태, 옵션별·전체 재고, 중복 옵션과 예상 금액을 검증한다.
화면이 확인한 금액과 현재 가격으로 계산한 금액이 다르면 `PRICE_CHANGED`로
거부하고 새 금액을 확인하도록 안내한다. 조회한 가격을 서버 역할의
handler에서 다시 계산하며, 클라이언트가 보낸 가격을 신뢰하지 않는다.

주문 성공은 `DEMO-` 번호와 금액·상품 스냅샷을 반환한다. 실제 결제, 배송,
재고 차감, 관리자 주문 기록 생성은 하지 않는다. 영수증은 완료 화면의
지역 상태로만 유지하므로 새로고침하면 사라진다.

## 상태와 계산 기준

- 서버 데이터는 기존 TanStack Query를 사용한다.
- 검색·필터·정렬·페이지는 URL에 보존하며, 상품 목록으로 돌아올 때 유지한다.
- 장바구니와 찜은 `react-sample-shop` localStorage에 저장한다.
  복원 시 스키마를 검증하고 잘못된 저장 값은 무시한다.
- 장바구니에는 상품 ID·옵션·수량만 저장하고, 금액과 재고는 현재 상품
  데이터에서 계산한다. 삭제되거나 판매를 중지한 상품은 경고를 표시한다.
- 같은 옵션은 합산한다. 옵션당 최대 99개, 장바구니 최대 50개 옵션,
  찜 최대 100개를 허용한다. 수량은 정수이며 재고 한도 안에서 주문한다.
- 상품 합계 10만 원 이상은 무료 배송, 미만은 3,000원이다.
- 모의 배송 정보는 React Hook Form과 Zod로 검증한다. 기본 예시 정보로
  체험 가능하며 배송 정보는 localStorage에 저장하지 않는다.
- 주문 실패 시 입력·장바구니를 유지하고 상품을 재조회한다.
  주문 성공 후에만 장바구니를 비운다.

## 코드와 검증

`features/shop`은 쇼핑 UI, 검색·장바구니 계산, 주문 API와 mutation을 소유한다.
`stores/shop-store.ts`는 클라이언트 장바구니·찜을 관리한다.
`mocks/shop-handlers.ts`는 같은 관리 상품 fixture로 모의 주문을 검증한다.

Storybook의 `Features/Shop`과 `Pages/Shop`에서 상품 카드, 구매 옵션,
주문 폼의 기본·검증 오류·저장 오류·로딩 상태와 목록·장바구니를 확인한다.

```bash
pnpm test src/features/shop src/stores/shop-store.test.ts
pnpm test:e2e e2e/shop.e2e.ts
pnpm verify
```
